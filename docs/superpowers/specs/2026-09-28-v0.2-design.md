# pcdlint v0.2 — Round Out the Product

Date: 2026-09-28
Status: approved for implementation
Scope: seven items, two phases

## Goal

Take pcdlint from "reports findings" to "acts on findings" (`--fix`, `--diff`,
SARIF) while closing the three measured accuracy gaps in the taint engine
(branch handling, interprocedural propagation, missing sources).

## Measured baseline (2026-09-28, Python 3.14)

124 tests pass, 91% total coverage, `taint.py` at 86%.

| Claim in brief | Measured result |
|---|---|
| Interprocedural depth > 1 broken | Forward-ordered chains resolve to depth 4+. Reverse-ordered depth 3 fails. Callee returning a `set` or unsorted `json.dumps` loses that fact. Attribute callee (`helpers.f()`) unresolved. `_MAX_FLOW_PASSES` at `taint.py:46` is dead. |
| Branch is just a flag | `if/else` assigning identical static `tools` → PCL004 FP. `for t in SPEC: tools.append(t)` over a list literal → PCL004 FP. `A if flag else B` with taint only in `A` → PCL001 FN. try/except taint → FN (source-order strong update, handler wipes `try`). |
| Missing taint sources | `time.time_ns`, `random.choices`, `random.sample`, `secrets.token_bytes`, `os.getpid` absent from `TAINT_SOURCES`. |
| `__main__.py` at 0% | **Stale.** Already 100% (4/4) via `test_pcdlint_main_module` and `test_main_module_guard_body_runs`. |

## Phase A — Analysis accuracy

### A1 · Taint sources

Extend `TAINT_SOURCES` in `taint.py` with five entries: `time.time_ns`,
`random.choices`, `random.sample`, `secrets.token_bytes`, `os.getpid`. The
matcher at `taint.py:278` already resolves dotted, bare, and nested-module
forms, so this is data only. One test per source.

### A2 · Branch sensitivity (targeted merge)

New `_run_block(stmts) -> _Bindings` in `TaintTracker`:

1. Snapshot `self._b` before entering an `ast.If` (or `ast.Try`).
2. Evaluate `body` against a copy, restore the snapshot, evaluate `orelse` /
   handlers against a second copy, restore again, then merge the two results.

Merge rules:

- `tainted`, `prefix_tainted`, `sets`, `json_unsorted`, `json_flows`,
  `tools_mutated` — **union** (may-analysis; taint on either path is reported).
- `static` — kept **only when both arms assign it and agree**, else dropped.
- `branch` flag — set only when the two arms **disagree** on assigning the name.

`ast.IfExp` gets the same treatment at expression level inside
`_track_target_value`.

Split `in_branch` into `in_conditional` (If / IfExp / Try only) and the
existing loop flag. `track_expr_stmt` marks `tools.append(...)` mutation only
on `in_conditional`, or in a loop whose iterator is a set/unresolved value —
not `for t in SPEC` where `SPEC` is a list literal.

Expected effect on the measured cases:

- `if-same-both` (identical static both arms) → no `branch` flag → PCL004 silent.
- `if-taint/else-static` → union keeps taint → PCL001 still fires (true positive preserved).
- `ifexp-taint-in-true` → PCL001 now fires (FN fixed).
- `try/except` → handler arms start from the pre-`try` snapshot → PCL001 fires (FN fixed).
- `loop-append-static` → PCL004 silent; `if-append` (arms disagree) still reported.

### A3 · Interprocedural fixpoint + function summaries

- `_track_tree` in `analyzer.py` converges on **summary stability** instead of
  `range(_MAX_PASSES)`: loop `assignment walk -> build_function_returns` until
  the summaries stop changing, hard-capped at 16 iterations. The cap is a cost
  ceiling; the existing `!= origin` equality check guarantees convergence on
  cycles. Delete dead `_MAX_FLOW_PASSES`.
- Widen `_func_returns: dict[Key, TaintOrigin]` to
  `_func_summaries: dict[Key, FuncSummary]`, a frozen dataclass in `models.py`:

  ```python
  @dataclass(frozen=True)
  class FuncSummary:
      origin: TaintOrigin | None
      is_set: bool
      json_flows: frozenset[int]
  ```

- Consume it in `_track_target_value` (call branch) and
  `get_taint_origin_of_node`, so `def get_tools(): return {a, b, c}` taints
  `tools` and `def payload(): return json.dumps(d)` keeps its PCL002 flow.

**Explicitly out of scope:** cross-module and attribute-call callees
(`helpers.make_stamp()`). That is module resolution, not interprocedural depth.

**Risk:** A2 rewrites statement-level state propagation. Phase A lands first
with the full suite green before any Phase B work starts.

## Phase B — Workflow surface

### B0 · Fix spans on `Diagnostic`

`Diagnostic` gains `edits: tuple[TextEdit, ...]`:

```python
@dataclass(frozen=True)
class TextEdit:
    start_line: int   # 1-based
    start_col: int    # 0-based UTF-8 byte offset within the line
    end_line: int
    end_col: int
    replacement: str
```

Columns are UTF-8 byte offsets because Python's `ast.col_offset` is bytes, not
characters. Splicing encodes the affected line(s) and slices bytes.

`fix_suggestion` stays as the human-readable string. Rules that know their fix
populate `edits`; every other rule leaves it empty.

### B1 · `--fix`

New `src/pcdlint/fixer.py`.

- **PCL002** — the insertion anchors after the **last argument** (or the last
  keyword's value when one exists), never before the closing paren. That keeps
  a trailing comma valid — `json.dumps(x,)` becomes
  `json.dumps(x, sort_keys=True,)` — and needs no source text. When the call has
  no arguments at all there is nothing to lead with a comma, so the keyword goes
  immediately before `)` instead. When a `sort_keys=` keyword is already present
  but not `True`, **replace that keyword's value** rather than inserting, so a
  duplicate keyword argument can never be produced.
- **PCL003** — wrap the *argument's* span in `sorted(...)` as **two insertions**,
  `sorted(` at the argument's start and `)` at its end. This requires PCL003
  diagnostics to record the argument node's span, not the call's: `join(x)`,
  `str(x)`, and `f"{x}"` each bracket `x`. Conversion and format specs
  (`f"{x!r}"`) live outside the value node, so wrapping the value alone is
  correct. Two insertions also mean the fix needs no source text.
- Application: group edits by file, sort ascending, drop any edit overlapping an
  already-accepted one, splice back-to-front, rewrite in place.
- Before writing, `ast.parse` the rewrite; a result that no longer parses is
  reported and skipped. Losing a finding is recoverable, corrupting a file is not.
- Rules with no edits are counted as skipped and reported in the summary.
- After writing, **re-analyze** the modified source so the exit code and
  output reflect what still fails.
- Unfixable findings (PCL001, PCL004) are never modified.

**Revised during implementation:** the original plan had the fixer read source
text to decide where the comma goes. Anchoring on the last argument instead
makes every edit derivable from AST spans alone, so `RuleEngine.run` never
needs the source and `fixer.py` stays a pure `str -> str` function.

### B2 · `--format sarif`

SARIF 2.1.0 on stdout:

- `runs[0].tool.driver` — name `pcdlint`, `__version__`,
  `informationUri` from `pyproject` Homepage, and a `rules` array covering all
  four `KNOWN_RULE_IDS` with `shortDescription` and `helpUri`.
- `results[]` — `ruleId`, `level` (`error` / `warning` from severity),
  `message.text`, and `locations[].physicalLocation` with
  `artifactLocation.uri` and `region.startLine` / `startColumn`.
- URIs are repo-relative POSIX paths (backslashes converted).
- Exit codes and `--fail-on-warn` behave exactly as they do for `text`/`json`.

### B3 · `--diff [REF]`

- `argparse` argument with `nargs="?"`, `const="HEAD"` — so bare `--diff`
  means "changes vs HEAD".
- Run `git diff --unified=0 --no-color --no-ext-diff <REF> -- <paths>` via
  subprocess, and `git rev-parse --show-toplevel` for path normalization.
- Parse `@@ -a,b +c,d @@` headers into the set of added line numbers in the
  new file: `range(c, c + d)`; `d == 0` contributes nothing.
- Keep a diagnostic only when its line is in the changed set for its file.
  Diagnostics are still sorted and reported as usual afterwards.
- **Known limitation, surfaced while testing:** a diagnostic points at the line
  where the value *reaches* the prompt (the `create()` call), not where it was
  defined. Editing a definition while leaving its call site untouched therefore
  hides that finding. Strict line filtering is what the flag promises and what
  keeps PR CI fast, so the limitation is documented in `--help` and the README
  rather than papered over with file-level filtering.
- Paths in the diff are repo-relative; diagnostic paths may be relative to the
  cwd or absolute. Normalize both sides against the toplevel before comparing.
- git missing, not a repo, or unknown ref → message on stderr, exit 2 (same
  contract as "a path could not be analyzed"). Unparseable files still report
  their own errors regardless of `--diff`.

### B4 · CI upload

Add a SARIF upload step to `.github/workflows/ci.yml`:

- runs `pcdlint check src/ tests/ --format sarif > pcdlint.sarif`,
- uploads with `github/codeql-action/upload-sarif@v3`,
- `permissions: security-events: write`,
- `continue-on-error: true` so repositories without code scanning enabled do
  not turn CI red.

### B5 · Closeout

- Version `0.1.0` → `0.2.0` in `pyproject.toml` and `src/pcdlint/__init__.py`.
- README: `--fix`, `--format sarif`, `--diff`, the five new taint sources, and
  a Code Scanning snippet.
- CLAUDE.md: new commands and updated rule/pipeline notes.
- `__main__.py` coverage: already 100%. Add only the missing assertion — the
  guard body exiting `1` when findings exist — via `runpy`.

1. All 124 existing tests still pass unchanged (no re-baselining).
2. The four measured branch FPs/FNs and the three interprocedural gaps have
